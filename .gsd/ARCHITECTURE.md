## Overview

Nutrient Earth is a production-grade, evidence-grounded health and nutrition platform. It provides personalized health insights, goal-oriented scientific research, and deterministic nutrition computations through a multi-tier architecture:
- **Presentation Layer**: Flutter client (Android, iOS, macOS, Web, Windows) utilizing Riverpod for unidirectional state management.
- **Application & Domain Layer**: Clean Architecture domain models, intent classification, evidence verification, and deterministic nutrition math.
- **Backend Infrastructure Layer**: Supabase Auth (JWT), Supabase PostgreSQL 15 with strict multi-tenant Row Level Security (RLS), and Supabase Edge Functions (Deno).

## Components

### 1. Presentation & UI (`client/lib/features/`, `client/lib/core/design_system/`)
- **Purpose**: Render responsive health interfaces, diurnal greetings, research query inputs, result modals with evidence badges, and privacy disclosures.
- **Location**: `client/lib/features/today/`, `client/lib/features/home/`, `client/lib/core/design_system/`
- **Key Files**:
  - `today_screen.dart`: Core entry hub displaying greeting, daily plan, learn articles, and research trigger.
  - `research_result_modal.dart`: Bottom-sheet modal displaying qualitative evidence ratings, PMID/DOI citations, practical steps, and history persistence.
  - `privacy_data_modal.dart`: Transparent user health data governance and encryption modal.
  - `ne_tokens.dart`: Design token system (colors, typography, spacing, border radii).
  - `today_state.dart`: Riverpod state notifier managing research processing, query history, and diurnal state.

### 2. Domain & Scientific Intelligence (`client/lib/core/domain/`)
- **Purpose**: Deterministic health calculations, citation validation, research intent routing, and personalized goal alignment.
- **Location**: `client/lib/core/domain/`
- **Sub-domains**:
  - `orchestration/`: `ResearchOrchestrationPipeline` coordinates the 9-stage inquiry lifecycle.
  - `evidence/`: `CitationValidator` ensures DOI/PMID validity and checks evidence hierarchies (Systematic Review, RCT, Cohort).
  - `nutrition/`: `NutritionComputationEngine` calculates Atwater general energy distributions, net carbohydrates, and gram-weight scaling.
  - `personalization/`: `GoalAlignmentEvaluator` identifies supplement duplicates (e.g. D3 vs D inquiries) and checks health contraindications.
  - `answer_contract/`: `StructuredResearchAnswer` schema defining immutable contract between AI engines and UI presentation.

### 3. Application Services & Data Persistence (`client/lib/core/services/`)
- **Purpose**: Orchestrate communication between client UI, Supabase Edge Functions, and Supabase PostgreSQL.
- **Location**: `client/lib/core/services/`
- **Key Services**:
  - `research_pipeline_service.dart`: Dispatches inquiries to edge synthesizer with graceful fallback to local orchestration.
  - `research_persistence_service.dart`: Executes atomic multi-row insertions into `public.ai_messages` satisfying composite relational constraints.
  - `profile_repository.dart`: Retrieves and updates authenticated user clinical profiles.
  - `learn_repository.dart`: Manages peer-reviewed educational articles with offline fallback.
  - `diurnal_service.dart`: Computes circadian-aligned morning, afternoon, and evening health guidance.

### 4. Supabase Backend & Edge Runtime (`supabase/`)
- **Purpose**: Secure serverless execution, health privacy enforcement, and multi-tenant persistence.
- **Location**: `supabase/`
- **Subcomponents**:
  - `functions/research-synthesizer/`: Deno edge function enforcing cryptographic Bearer token validation, server-side biometric PII classification (`ServerHealthPrivacyGuard`), circuit breaker management, and DeepSeek model synthesis.
  - `migrations/`: Idempotent SQL schema migrations (`greenfield_schema`, `rls_security_hardening`, `cross_conversation_authorization_hardening`).
  - `tests/`: pgTAP automated regression and tenant isolation test suites.

## Data Flow

1. **User Inquiry Trigger**: User enters a query into `ResearchSearchBar` (e.g., "Does magnesium bisglycinate improve sleep?").
2. **State & Orchestration Dispatch**: `TodayStateNotifier` calls `ResearchPipelineService.processInquiry()`.
3. **Authentication & Token Derivation**: Client attaches Supabase session Bearer JWT to the Edge Function request.
4. **Edge Security & Privacy Classification**: `research-synthesizer` validates token via `supabase.auth.getUser()`, blocks sensitive health PII from leaving the trusted perimeter, and routes general queries to DeepSeek or curated knowledge fallback.
5. **Contract Validation**: Responses are validated against `StructuredResearchAnswer` (rejecting manufactured numerical percentages).
6. **Result Presentation**: UI renders the answer summary, qualitative evidence badge, validated citations, and action steps.
7. **Atomic History Persistence**: User taps "Save to History"; `ResearchPersistenceService` executes an atomic multi-row insert into `public.ai_messages` verifying `(conversation_id, user_id)` foreign keys.

## Integration Points

| External Service | Type | Purpose | Security Controls |
|---|---|---|---|
| **Supabase Auth** | OAuth / Passwordless | User identity and session management | Short-lived JWTs (3600s), secure local storage |
| **Supabase PostgreSQL 15** | Relational Database | Health metrics, reports, conversations, messages | RLS `TO authenticated`, composite FKs, encrypted storage |
| **Supabase Edge Functions** | Deno HTTP API | Research synthesis & privacy gatekeeper | Cryptographic Bearer token verification, CORS headers |
| **DeepSeek AI (Hugging Face)** | LLM Inference | Scientific text synthesis | Circuit breaker, PII scrubbing, deterministic fallback |

## Conventions

- **Architecture**: Clean Architecture with feature-first presentation widgets and isolated domain services.
- **State Management**: Flutter Riverpod (`StateNotifierProvider`, `Provider`).
- **Database Security**:
  - Zero raw `auth.uid() = user_id` without conversation ownership checks.
  - RLS policies specify `TO authenticated` and wrap functions in `(select auth.uid())`.
  - Composite foreign keys `(conversation_id, user_id)` enforce ownership at storage engine layer.
- **Testing**:
  - Domain and unit tests: `package:flutter_test` (`client/test/`).
  - Database and RLS tests: pgTAP via `supabase test db` (`supabase/tests/`).
